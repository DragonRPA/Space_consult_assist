# 세종텔레콤(비즈메시지) + AWS 연동 프로토타입

## 개요
이 프로토타입은 향후 실제 세종텔레콤의 비즈메시지 API(알림톡, SMS 등)를 당사의 AWS 서버리스 아키텍처에서 안정적으로 호출하고, 전송 결과를 콜백(Webhook)으로 수신하기 위한 뼈대 코드 및 인프라 구성을 담고 있습니다. 현재 프로젝트에 당장 적용되지는 않지만, 미래 확장 시 발생할 수 있는 주요 병목(IP 제한, 폴백 등)을 선제적으로 정의하고 검증하기 위함입니다.

## 프로토타입 구성 요소
1. **`aws_cdk_stack.py`**: AWS CDK를 활용한 인프라스트럭처 정의(Mock). Lambda가 외부 통신 시 고정 IP를 가질 수 있도록 VPC, NAT Gateway, Elastic IP를 구성하는 방법론 포함.
2. **`lambda_sender.py`**: 카카오 알림톡 전송 요청 및 실패 시 일반 문자로 전환(Fallback) 발송을 처리하는 백엔드 로직.
3. **`lambda_webhook.py`**: 세종텔레콤으로부터 전송 성공/실패 여부를 비동기로 전달받아 DB(또는 SQS)에 기록하는 웹훅 수신기.

## ⚠️ 예상되는 주요 이슈 및 대비책 (사전 기록)

### 1. 동적 IP 환경(Lambda)과 세종텔레콤 방화벽 정책 충돌
- **현상**: 세종텔레콤을 비롯한 국내 기간통신사업자 API는 보안을 위해 사전에 등록된 고정 IP(White IP)로부터의 요청만 허용합니다. 기본 상태의 AWS Lambda는 퍼블릭 통신 시 수시로 IP가 변동됩니다.
- **해결책/대비책**: 
  - Lambda를 반드시 VPC 내 프라이빗 서브넷에 배치해야 합니다.
  - 퍼블릭 서브넷에 NAT Gateway와 Elastic IP(고정 IP)를 할당하고, 프라이빗 서브넷의 아웃바운드 트래픽을 NAT Gateway로 라우팅합니다.
  - 이 고정된 Elastic IP를 세종텔레콤 측에 화이트리스트로 등록 요청해야 합니다.
  - **주의**: NAT Gateway는 시간당 유지 비용 및 트래픽 처리 비용이 발생하므로 인프라 예산 산정에 반영되어야 합니다.

### 2. 알림톡 템플릿 검수 지연 및 변수 매핑 오류
- **현상**: 알림톡은 사전에 카카오의 승인을 받은 템플릿 텍스트와 정확히 일치해야 발송됩니다. 띄어쓰기나 줄바꿈, `#{변수명}` 매핑이 하나라도 어긋나면 전송이 실패합니다.
- **대비책**: 
  - 개발 환경(Sandbox)과 운영 환경에서 동일한 템플릿 포맷을 관리하는 '템플릿 저장소(DB 또는 설정 파일)'를 별도 운영해야 합니다.
  - `lambda_sender.py`에 구현된 바와 같이, 알림톡 전송 실패를 대비해 자동으로 대체 문자(LMS/SMS)를 조립하여 쏘는 **Fallback 로직**이 백엔드 단에 필수적입니다.

### 3. 비동기 웹훅 수신량 급증 (Throttling 및 병목)
- **현상**: 한 번에 수천 건의 메시지를 발송하면, 수 분 내로 세종텔레콤 서버로부터 엄청난 양의 콜백(성공/실패 결과) 웹훅 요청이 밀려옵니다. 
- **대비책**: 
  - `lambda_webhook.py`가 직접 DB에 Write를 수행하면 DB 커넥션 병목이나 타임아웃이 발생할 수 있습니다.
  - 웹훅 API Gateway 뒤에는 단순히 AWS SQS나 EventBridge를 두어 이벤트를 적재만 하고 빠르게 200 OK를 응답한 뒤, 별도의 워커 Lambda가 큐를 배치(Batch)로 비우며 DB를 업데이트하는 비동기 버퍼 구조를 갖춰야 합니다.
